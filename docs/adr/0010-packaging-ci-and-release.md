# ADR 0010: Packaging, llama.cpp Build, License Notices, CI, and Releases

## Status

Accepted

## Context

Semma distributes self-contained `.rpm` and `.deb` packages bundling a standalone Python 3.13 runtime, trimmed PySide6/Qt Widgets libraries, and `llama.cpp` shared libraries, built and verified in clean containers via GitHub Actions.

## Decisions

### 1. Self-Contained Packaging Layout (`packaging/nfpm.yaml`, `scripts/package.sh`)
- A single `nfpm.yaml` specification produces both `.rpm` and `.deb` packages from `build/stage`.
- Everything Semma runs on lives under `/usr/lib/semma`: a standalone Python 3.13 interpreter (glibc-only, statically linked, stripped of `libpython`, Tcl/Tk, IDLE, pip, and headers), locked dependencies, and `llama.cpp` libraries. The model is downloaded at runtime.
- `/usr/bin/semma` invokes the bundled Python with `-I` (isolated mode) so user `PYTHONPATH`, current working directory, and user `site-packages` never interfere.
- Bytecode is precompiled with `unchecked-hash` during packaging because `/usr` is read-only at runtime and file mtimes vary across installs.
- Desktop and systemd files are generated by the same code path as `semma install`.
- PySide6-Essentials (~250 MB) is trimmed via an explicit allow-list (missing paths fail the build) to only Qt Widgets for Wayland/X11. `libqgtk3.so` is excluded so GTK 3 is not pulled in alongside Qt; `libqxdgdesktopportal.so` handles desktop integration over D-Bus instead.
- `ca-certificates` is a hard dependency so the bundled Python can verify HTTPS model downloads on bare Debian/Ubuntu systems. Vulkan, `ffmpeg`, Qt desktop libraries, and Tesseract (`libtesseract5` + English on Debian; `tesseract-libs` on Fedora) are `Recommends` so minimal/headless installs stay free of desktop dependencies.

### 2. llama.cpp Build (`scripts/build-llama.sh`)
- Builds a pinned `llama.cpp` commit (libraries only: `libllama`, `libmtmd`, `ggml`; no CLI/server) inside a container (`ubuntu:24.04` default for glibc 2.39 compatibility) with `GGML_BACKEND_DL` enabled so one package carries every x86-64 CPU backend variant plus Vulkan.
- `glslc` compiles Vulkan shaders at build time; the backend loads system `libvulkan` dynamically at runtime.
- Libraries use `$ORIGIN` rpath so they resolve siblings in their own directory. The Vulkan backend is installed as `libsemma-ggml-vulkan.so` (a name `ggml` does not auto-load) so `embedder.py` loads it explicitly only in GPU workers.
- `llama.cpp` licenses are copied beside the libraries in `build/llama` so cached CI builds still supply them to `scripts/notices.py`.
- Bumping the pinned `llama.cpp` commit requires `tests/test_parity.py` to pass and `embedder.py` `ctypes` structs to match the headers.

### 3. License Notices (`scripts/notices.py`)
- Notices are collected before the PySide6 trim so every bundled wheel is accounted for; any wheel lacking license files fails the build unless mapped to its upstream source tag.
- Qt test/example/doc licenses are excluded (none are packaged), and the shiboken support header's inline PSF license is captured.
- Debian packages also install notices at `/usr/share/doc/semma/copyright` (which minimized Ubuntu containers retain even when stripping other docs).

### 4. Maintainer Scripts (`packaging/postinstall.sh`, `preremove.sh`, `postremove.sh`)
- First-install vs. upgrade detection follows RPM (`1` vs. `>=2`) and dpkg (`configure` with empty vs. non-empty prior version) conventions so upgrades never re-enable a service an administrator disabled.
- Removal scripts act only on true removal (`0` on RPM, `remove` on dpkg; `purge` follows `remove`), never on upgrade.
- User systemd calls target only active/lingering sessions (no-op in containers without systemd), apply bounded timeouts so a stuck user session never stalls `dnf`/`apt`, touch only the packaged unit (respecting a user's own `~/.config` unit from `semma install`), and restart/reload KRunner so it discovers or forgets the D-Bus plugin.

### 5. Package Verification, CI, and Release Workflows
- `scripts/check-package.sh` verifies both `.rpm` and `.deb` in clean Fedora/Ubuntu containers: checks license notices, verifies headless daemon/CLI library links without recommends, checks upgrade preserves disabled service state, installs GUI recommends (excluding Vulkan/ffmpeg/Tesseract), verifies offscreen Qt onboarding -> main window flow (exiting non-zero on Qt slot exceptions), and runs real CPU indexing + semantic search + D-Bus activation.
- `.github/workflows/tests.yml` runs `pytest` on push/PR inside `dbus-run-session` with `QT_QPA_PLATFORM=offscreen` (skipping GPU/model tests).
- `.github/workflows/package.yml` caches `build/llama` (keyed on `scripts/build-llama.sh`), the model (keyed on `embedder.py`), and upstream license downloads (~175 MB, version-keyed). Branch pushes cancel older runs; release tags are never cancelled.
- `.github/workflows/release.yml` (triggered by `v<version>` tags from `scripts/release.sh` or manually on `main`) runs the package workflow and publishes the GitHub release (suffixes like `-beta.1` become prereleases). Manual runs create the tag at the built commit using `GITHUB_TOKEN` (which intentionally does not trigger a duplicate workflow run).
- `scripts/gnome_devkit.sh` launches a nested `mutter-devkit` GNOME Shell inside a private `dbus-run-session` (avoiding collisions with KDE Plasma's well-known bus names) while `scripts/gnome_bridge.py` bridges only `org.gnome.Shell.SearchProvider2` back to the host session bus.
